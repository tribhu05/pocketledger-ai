# PocketLedger AI — System Architecture

PocketLedger AI is built upon a **local-first, privacy-by-design architecture** designed specifically for freelancers, consultants, and independent creators who require structured expense tracking without exposing sensitive client financial documents to third-party cloud AI vendors.

## 2. Core Processing Pipeline Stages

### Stage 1: Ingestion & Boundary Check
- Files are accepted in `.pdf`, `.png`, `.jpg`, `.jpeg`, and `.webp` formats.
- Uploads are strictly bounded at 15 MB per document.
- Filenames are sanitized, stripped of path traversal characters, and written with unique UUID prefixes to the local `uploads/` directory.

### Stage 2: Dual-Engine Text Extraction
- **PDF Invoices (Digital First):** Invoices generated by Stripe, AWS, GitHub, Hetzner, Google, and Zoom are parsed digitally using `pypdf`, preserving exact numbers, vendor headers, and VAT blocks without raster degradation.
- **Photo Receipts (Tesseract OCR):** Physical camera receipts undergo image contrast enhancement and grayscale conversion before processing via local Tesseract OCR.
- **Graceful Fallback:** If Tesseract is not installed on the host machine, PDF documents continue processing without issue, and status indicators clearly alert the user.

### Stage 3: Semantic Understanding via Gemma 2B
- The extracted text is passed to Google's open-weight `gemma2:2b` instruct model running locally on Ollama.
- Temperature is locked to `0.1` with `format="json"` to ensure deterministic structured outputs.
- A strict prompt mandates schema adherence and explicitly commands: *"Never invent, hallucinate, or assume missing values. If not visible in text, use null."*

### Stage 4: Deterministic Validation & Reconciliation
Before any record reaches the human review screen, it passes through pure application logic:
- **Math Reconciliation Rule:** `subtotal + tax ≈ total` (within 0.05 rounding tolerance).
  - If amounts reconcile: flagged as `reconciled`.
  - If amounts differ: flagged as `mismatch` with a clear explanation:
    *`Reconciliation mismatch: Subtotal ($20.00) + Tax ($2.00) = $22.00, differing from Total ($28.50) by $6.50. Please review source receipt.`*
- **Date Normalization:** Dates parsed into standard ISO-8601 (`YYYY-MM-DD`). Future dates or suspicious years are flagged with warnings.
- **Currency Standardization:** Currency symbols (`$`, `€`, `£`, `₹`, `¥`) mapped to ISO-4217 three-letter codes (`USD`, `EUR`, `GBP`, `INR`, `JPY`).
- **Category Taxonomy:** Mapped to standardized freelance tax categories (Software & SaaS, Office Supplies, Hardware, Travel, Meals, Professional Services, Utilities, Other).

### Stage 5: Human Review & Audit Trail
- Uncertain records require user confirmation.
- Every manual edit is diffed and stored in the `user_edits` audit log.
- Raw OCR text and raw model output are permanently retained alongside the record.

### Stage 6: Injection-Safe CSV Export
- Multi-currency totals are strictly segregated (never summed together into confusing blended totals).
- Every cell starting with formula triggers (`=`, `+`, `-`, `@`, `\t`, `\r`) is prepended with a single quote (`'`) to neutralize CSV injection attacks in spreadsheet viewers.
